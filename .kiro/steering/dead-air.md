# Dead Air project constraints

- This is a fictional practice and discussion tool, not an emergency response product.
- Use only fictional roles and sample data. Never request real names or contact details.
- Do not send messages or provide emergency instructions.
- Keep runtime behavior local to the browser with no network requests, accounts, analytics, or backend.
- Keep the project static and free to run and demo; do not add paid services, APIs, AI, or dependencies without asking.
- `src/domain/communication-network.ts` is Kiro's domain module. Keep reachability logic there; do not duplicate it in UI code.
- Fictional role communication modes and route modes are simplified exercise assumptions. Filter mismatched destination routes before calling the analyzer; never claim they guarantee real-world accessibility.
- Keep follow-up worksheet values in page memory only. Owner choices must be fictional role labels, not people's names.
- Routes are directed. Represent two-way communication as two separate directed routes.
- Preserve keyboard access, visible focus, readable contrast, responsive layouts, and reduced-motion support.
- Do not add jumpscares or unrelated features.
